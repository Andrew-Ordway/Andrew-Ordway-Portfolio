BrahMos Ramjet Thermodynamic Analysis

With my newfound knowledge of thermodynamics from ENGRD 2020, I decided to apply what I learned to analyze ramjets and specifically the BrahMos Ramjet. On a high level, ramjet engines are open Brayton cycle engines used when aircraft are already traveling at incredibly fast supersonic speeds; however, ramjets have a couple key differences.

Firstly, instead of relying on a compressor as is used in conventional open Brayton cycles, the ramjet rather uses the aircraft's high speeds to compress incoming air. Because the ramjet does not have a compressor, it also does not have a turbine (which is typically needed to drive the compressor), allowing for all of the engine's work to be transferred into thrust. With no turbine, compressor, or shaft connecting the two, ramjets actually have no moving parts. Consequently, ramjets are only beneficial for aircraft traveling at speeds upwards of Mach 2 (meaning also that these aircraft must have some other booster to initially reach these supersonic speeds). In other words, ramjets are primarily used to "feed" off the aircraft's speed, becoming exponentially more powerful the faster the aircraft is moving.

Control Volume: Heat, Mass, and Work Transfers

So what exactly happens in a Brayton cycle with no compressor or turbine? First, the forward speed of the aircraft compresses air into the inlet. From there, the inlet directs the air into a diffuser, which slows it down—converting much of the air's kinetic energy to potential energy in the form of pressure and in turn heat. When a ramjet flies at supersonic speed, the incoming air must be slowed down before fuel can burn properly. This is done using a series of oblique shock waves that gradually reduce the air's speed, followed by a normal shock that brings the airflow to subsonic speed before combustion.

Once the pressure is great enough—typically when the air has slowed to Mach 0.3-0.5—the compressed air is mixed and ignited with fuel in a combustion heat exchanger. Through the combustor, energy is added to the airflow, and the resulting high-energy flow is accelerated through a converging-diverging nozzle to produce thrust.

A used change in design is that when the aircraft speed reaches above Mach 5, the ramjet engine begins to fail because the normal shock required to achieve subsonic speeds before combustion causes extremely high temperatures and low pressures.

Arduino LED Matrix Pong Game

The Final Product

This project is a minimalist, hardware-based version of the classic Pong game, built using an Arduino UNO, a joystick module, and an 8x8 LED matrix display. The game runs entirely on Arduino, using no external screen or PC, and features interactive visual feedback for game events.

The player controls a paddle using an analog joystick to keep the ball in play. The game simulates basic physics, including bouncing off walls and paddle collision detection. When the player misses the ball, the game responds with a visual indicator (the entire screen lights up red) to signal game over before resetting.

Circuitry and Coding Components

Circuitry

The circuit uses a breadboard-based prototyping setup that organizes connections between the Arduino, joystick, and LED matrix:

Joystick Connections:

  • VCC (red) → Arduino 5V via breadboard power rail
  • GND (yellow) → Arduino GND via breadboard ground rail
  • VRx (purple) → Arduino A0 for X-axis paddle control
  • VRy (teal) → Arduino A1 (available for future features)

LED Matrix Connections:

  • Data (orange) → Arduino Digital Pin 6
  • VCC (red) → Arduino 5V
  • GND (white) → Arduino GND

The joystick module is mounted directly on the breadboard for easy access during gameplay, while color-coded jumper wires provide clean signal routing between components. USB power supplies sufficient current for the LED matrix at the reduced brightness level used in gameplay.

Software Architecture

The game is programmed in C++ using the Arduino framework and Adafruit NeoPixel library for LED control. Key software features include:

Game State Management:

  • Real-time position tracking for paddle and ball
  • Collision detection algorithms for walls and paddle
  • Game-over state handling with visual feedback

Input Processing:

  • Analog-to-digital conversion of joystick position
  • Threshold-based paddle movement with deadzone handling
  • Smooth, responsive control at 10Hz update rate

Display Rendering:

  • Efficient pixel addressing using serpentine matrix mapping
  • Frame-based animation at configurable update rates

Physics Engine:

  • Wall collision detection and reflection
  • Paddle hit detection with dynamic angle adjustment based on contact point
  • Ball direction varies depending on which part of the paddle makes contact
